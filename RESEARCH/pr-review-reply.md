Thanks, this is a good review. Done, all in the force-pushed `xmpp-calls-pr` (A, this PR) and a new draft PR B stacked on it.

**1. Split.** The seam was clean, no duplicated guts. B (`xmpp-omemo-pr`, draft, link below) holds exactly the OMEMO store rewrite: lock, shared storage data, atomic 0600 writes, refusing an unreadable store, the one-shot sender never using OMEMO, the device-list refresh, and `plaintext_peers`. `agent_peers` stayed in A because `xmpp_message` needs it. **2. CI.** The workflow installs `requirements-calls.txt` and sets `XMPP_REQUIRE_CALL_DEPS=1`, so a missing call package is an error instead of a silent skip. Verified: with the packages hidden, the run fails. A: 473 passed, 9 skipped on 3.14 (I also condensed my own tests: the config validation cases were about 100 parametrized cases of one loop, now two tests that list every failing case; coverage of the code is unchanged).

**3. Version.** `plugin.yaml` is 0.5.0, CHANGELOG has the 0.5.0 heading.

**xmpp_message.** It is now offered whenever the adapter is connected. It does not need `calls.enabled` or aiortc. There is a test with calls off and no call packages, and the hand-off example in the README no longer enables calls on the worker.

**3.13 failures.** Environment dependent, thanks for checking. My machine has no `/etc/mime.types`, and Python 3.13's `mimetypes` only knows `.ogg` from that file (3.14 has it built in). Hosts without that file are common: NixOS, and the stock Alpine, Debian/Ubuntu, Fedora and Arch container images (I checked `python:3.13-slim`, `alpine`, `ubuntu`, `fedora` and `archlinux`: none has `/etc/mime.types`, and `python:3.13-slim` returns no type for `.ogg`, `.oga` or `.m4a`). I'll send a small separate PR for it.

**Optional call dependencies.** You were right: `hermes update` would prune them. I did not want to declare ~230 MB (PyAV's FFmpeg is most of it) for everyone, so with calls on the first start now builds an isolated Hermes environment with `pm.ensure_environment()` under `<hermes root>/environments/hermes-xmpp-calls/`, from `requirements-calls.txt`. It is outside the plugin folder and the main venv, so `hermes update` leaves it alone. Calls off means nothing is downloaded. A slow first build (over 25 s) does not hold up chat: calls start with the next reconnect. Hermes' own numpy and av still win. A `vendor/` folder is the fallback (older Hermes, or lazy installs off such as in Docker), and the log prints the command. I ran it for real on x86_64 and on two aarch64 VMs: 8 s and 17-20 s, about 230-250 MB. Reasoning is in the README ("Where the call packages live"). `av` now follows aiortc's own range (`>=14`).

**New since your review.** A fourth commit adds options that came out of live use, all with unchanged defaults: `greeting` takes a list and is cached like the filler, `ack_tone`/`warn_tone` take `false` or a sound file, `max_seconds: false` lifts the time limit, and the rate limits (`max_calls_per_hour`, `opening_max_chars`, `xmpp.agent_peer_limit`, `xmpp.message_tool_limit`) are configurable. More gateway status lines are no longer exchanged with a partner agent. Monocles Chat is now in the tested-clients list.
